# 编译与部署

## 编译依赖

需要：

- ARM 交叉编译器，例如 `arm-buildroot-linux-gnueabi-gcc`。
- 动态链接时需要目标固件 rootfs 中的 ARM 动态库：
  - `libdb.so`
  - `liboss.so`
  - `libcommfun.so`
  - `libcfapi.so`
  - `libifscfapi.so`
  - `libdbcspview.so`
- 静态 vendor-lib 链接时需要同架构静态库：（<span style="color: rgb(219, 39, 119);">***<mark data-color="#fee2e2" style="background-color: rgb(254, 226, 226); color: inherit;">没有源码和a文件，所以无法静态编译</mark>***</span>）
  - `libdb.a`
  - `liboss.a`
  - `libcommfun.a`
  - `libcfapi.a`
  - `libifscfapi.a`

这些库必须是目标设备同架构版本，不能用（编译器）主机系统库代替。

## 目录结构

推荐独立项目结构：

```text
ztedbcli/
  ztedbcli.c
  build.sh
  build_ztedbcli.sh
  lib/
    libdb.so
    liboss.so
    libcommfun.so
    libcfapi.so
    libifscfapi.so
    libdbcspview.so
  docs/
```

`lib/` 可以不提交到代码仓库；也可以在编译时通过 `ROOTFS` 或 `LIBDIR`指向外部 rootfs。

## 编译方式

如果依赖库已经放在 `./lib/`：

```sh
CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

如果有完整 rootfs：

```sh
CC=arm-buildroot-linux-gnueabi-gcc \
ROOTFS=/path/to/rootfs \
./build.sh
```

如果只想（编译时）指定库目录：

```sh
CC=arm-buildroot-linux-gnueabi-gcc \
LIBDIR=/path/to/rootfs/lib \
./build.sh
```

自定义输出路径：

```sh
CC=arm-buildroot-linux-gnueabi-gcc \
OUT=/tmp/ztedbcli \
./build.sh
```

## 静态链接

默认构建是动态链接：

```sh
CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

如果担心后续固件升级裁剪或改名 `libdb.so/liboss.so/libcommfun.so`，可以在 有 `.a` 静态库时使用：（<span style="color: rgb(219, 39, 119);"><mark data-color="#fee2e2" style="background-color: rgb(254, 226, 226); color: inherit;">目前没有</mark></span>`.a`<span style="color: rgb(219, 39, 119);"><mark data-color="#fee2e2" style="background-color: rgb(254, 226, 226); color: inherit;">文件无法静态编译</mark></span>）

```sh
STATIC=1 CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

这个模式会把 ZTE vendor libs 静态链接进 `ztedbcli`，但 libc、pthread、 rt、dl 等系统库仍可动态链接。通常这是最实用的模式。

如果工具链提供完整静态 libc，也可以尝试：

```sh
STATIC=1 FULL_STATIC=1 CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

全静态更依赖工具链，`dlopen`、NSS、pthread 等场景可能出现链接警告或运行时 限制。建议优先使用 `STATIC=1`，只有确认目标环境需要单文件且工具链支持时 再用 `FULL_STATIC=1`。

### BUNDLE 模式

如果没有 `.a`，但想避免依赖设备系统中的 ZTE `.so`，可以生成 bundle：

```sh
BUNDLE=1 CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

输出：

```text
ztedbcli.bundle/
  ztedbcli
  run.sh
  lib/
    libdb.so
    liboss.so
    libcommfun.so
    libcfapi.so
    libifscfapi.so
    libdbcspview.so
ztedbcli.bundle.tgz
```

设备上运行：

```sh
tar -xzf ztedbcli.bundle.tgz -C /tmp
/tmp/ztedbcli.bundle/run.sh help
```

这不是静态链接，但可以在目标系统删掉或改名 `libdb.so/liboss.so/libcommfun.so`时继续使用自带库。

参数说明：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `STATIC` | `0` | `1` 时查找 `libdb.a/liboss.a/libcommfun.a/libcfapi.a/libifscfapi.a` 并静态链接 vendor libs |
| `FULL_STATIC` | `0` | `1` 时传 `-static`，需要 `STATIC=1` |
| `UPX` （<span style="color: rgb(219, 39, 119);">**需要系统先安装upx工具包**</span>） | `0` | `1` 时构建后执行 `upx -9` |
| `BUNDLE` | `0` | `1` 时生成带本地 `.so` 和 `run.sh` 的 bundle |
| `UPX_BIN` | `upx` | 指定 UPX 路径 |
| `SYS_LIBS` | `-ldl -lpthread -lrt -lm` | 动态模式和 `STATIC=1` 非全静态时的系统库 |
| `FULL_STATIC_LIBS` | `-ldl -lpthread -lrt -lm` | `FULL_STATIC=1` 时额外链接库 |

重要边界：

- 只有 `.so` 时无法生成真正静态单文件；需要 `.a`。
- 如果没有 `.a`，可以随程序一起携带 `.so`，通过 `LD_LIBRARY_PATH` 指向 自带库目录运行，但这不是静态链接。

## 常见编译错误

### cannot find -ldb

含义：动态模式下链接器找不到 `libdb.so`，静态模式下找不到 `libdb.a`。

处理：

```sh
LIBDIR=/path/to/rootfs/lib CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

或复制库：

```sh
mkdir -p lib
cp /path/to/rootfs/lib/libdb.so lib/
cp /path/to/rootfs/lib/liboss.so lib/
cp /path/to/rootfs/lib/libcommfun.so lib/
cp /path/to/rootfs/lib/libcfapi.so lib/
cp /path/to/rootfs/lib/libifscfapi.so lib/
cp /path/to/rootfs/lib/libdbcspview.so lib/
CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

如果是 `STATIC=1`：

```sh
mkdir -p lib
cp /path/to/rootfs/lib/libdb.a lib/
cp /path/to/rootfs/lib/liboss.a lib/
cp /path/to/rootfs/lib/libcommfun.a lib/
cp /path/to/rootfs/lib/libcfapi.a lib/
cp /path/to/rootfs/lib/libifscfapi.a lib/
STATIC=1 CC=arm-buildroot-linux-gnueabi-gcc ./build.sh
```

### cannot find -loss

缺 `liboss.so`。处理方式同上。

### cannot find -lcommfun

缺 `libcommfun.so`。处理方式同上。

### undefined reference to `fabs` / `pow` / `floor`

`libcommfun.so` 依赖数学库 `libm`。默认脚本已经在 `libcommfun` 后追加 `-lm`。如果你覆盖了 `SYS_LIBS` 或 `FULL_STATIC_LIBS`，需要保留 `-lm`：

```sh
SYS_LIBS="-ldl -lpthread -lrt -lm" \
CC=arm-buildroot-linux-gnueabi-gcc \
./build.sh
```

### file in wrong format

通常是拿到了主机 x86/x86_64 版本库，或者交叉编译器架构和目标库架构不一致。 确认：

```sh
file lib/libdb.so
file lib/liboss.so
file lib/libcommfun.so
```

应显示 ARM ELF。

## 部署到设备

上传：

```sh
scp ztedbcli root@DEVICE_IP:/tmp/ztedbcli
```

设备上执行：

```sh
chmod +x /tmp/ztedbcli
LD_LIBRARY_PATH=/lib:/usr/lib /tmp/ztedbcli diag
```

如果设备库不在 `/lib:/usr/lib`，把实际库路径加入 `LD_LIBRARY_PATH`。

## 运行环境要求

`ztedbcli` 需要：

- `cspd` 已启动。
- `libdb.so` shared memory server 已初始化。
- 当前 IPC namespace 中存在 key 为 `0xffff` 的 SysV shared memory。
- `libdbcspview.so` 可被 `dlopen` 找到。
- `libcfapi.so` 已加载或被链接进 `ztedbcli`，用于提供 `CfGetWlanNum`。
- `libifscfapi.so` 已加载或被链接进 `ztedbcli`，用于提供 `GetRouteIFInfo`。
- 当前 shell 能访问和 `cspd` 相同的 shared memory namespace。

如果出现：

```text
DBShmCliInit warning
```

优先检查：

- 先跑 `ztedbcli diag`，确认动态库加载、`shmget`、`shmat` 和 `dbFindTbl("TelnetCfg")` 的具体状态。
- `cspd` 是否运行。
- `diag` 中 `shmget key=0xffff` 是否成功；如果失败，先看 errno。
- 是否出现 `Open libdbcspview.so failed`。如果是，设置 `LD_LIBRARY_PATH=/path/to/libs:/lib:/usr/lib`，或使用 bundle 的 `run.sh`。
- 是否在错误 chroot/container/namespace 中执行。
- `LD_LIBRARY_PATH` 是否指向了错误版本库。
- 编译时链接的库和设备运行时库是否来自同一固件。

当前 G7615 样本中，`DBShmCliInit()` 可能返回 `1610616996`，即 `0x600010a4`。公开的 `printbl.c` 示例不检查这个返回值，而是直接继续 `dbFindTbl()` / `dbGetDmValComm()`。因此这个值不能单独作为致命失败依据： 如果 `diag` 最后显示 `dbFindTbl TelnetCfg OK`，说明运行时 DB 已经可访问。 如果 `shmget` 或 `shmat` 失败，才需要继续排查 shared memory、权限或 IPC namespace。

### Open libdbcspview.so failed / undefined symbol: CfGetWlanNum

`libdb.so` 在 `DBShmCliInit` 内部会调用 `dlopen("libdbcspview.so")`。 这个库不是普通链接期依赖，所以即使 `ztedbcli` 本身能启动，也可能在初始化 DB client 时失败。

当前 G7615 已验证：`libdbcspview.so` 还需要 `CfGetWlanNum`，该符号由 `libcfapi.so` 提供；`libcfapi.so` 又需要 `GetRouteIFInfo`，该符号由 `libifscfapi.so` 提供。如果 `LD_DEBUG` 里看到：

```text
/lib/libdbcspview.so: error: symbol lookup error: undefined symbol: CfGetWlanNum
/lib/libcfapi.so: undefined reference to `GetRouteIFInfo'
```

需要重新用包含 `libcfapi.so`、`libifscfapi.so` 的新版脚本编译，或确保二者 被预加载。

处理方式：

```sh
find /lib /usr/lib /opt -name libdbcspview.so -o -name libcfapi.so -o -name libifscfapi.so 2>/dev/null

LD_LIBRARY_PATH=/opt/cu/apps/apps/root/lib:/lib:/usr/lib \
  /opt/cu/apps/apps/root/ztedbcli diag
```

临时验证也可以用：

```sh
LD_PRELOAD="/lib/libcfapi.so /lib/libifscfapi.so" \
LD_LIBRARY_PATH=/lib:/usr/lib \
/opt/cu/apps/apps/root/ztedbcli diag
```

如果你用 bundle：

```sh
/tmp/ztedbcli.bundle/run.sh diag
```
